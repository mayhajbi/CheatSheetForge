## שלב 1 — תכנון עם BMad Method

BMad הוא פריימוורק פתוח-קוד (MIT) לתכנון agile מונחה-AI, עם סוכני AI ייעודיים (Analyst, PM, Architect) ותהליך מובנה: ניתוח → תכנון → ארכיטקטורה → מסירה למימוש.

צעדים מוצעים:
- הרצת שלב ניתוח/PRD (ניתן להזין את מסמך ה-PRD הזה כ-Brief קיים, כדי לחסוך את שלב האנליזה מאפס).
- הרצת שלב Architecture, שם ייסגרו ההחלטות הטכניות מפרק 06 (בחירת LLM, Backend, ספריית מסמכים).
- יעד זמן: סיום עד תחילת שלב המימוש (מומלץ תוך 2–3 שעות).

## שלב 2 — מימוש עם Superpowers, בשלושה זרמים מקבילים

Superpowers הוא פלאגין ל-Claude Code שמטמיע מתודולוגיית פיתוח מובנית (14 skills): סיעור מוחות → מפרט → פיתוח מבודד (git worktrees) → TDD (כתיבת בדיקה כושלת לפני קוד) → בדיקת קוד.

חלוקה ל-3 זרמי עבודה מקבילים, כל אחד ב-branch נפרד (תואם לעקרון ה-worktrees של הכלי, שנועד למנוע התנגשויות בין מפתחים) — **פירוט מלא, כולל מבנה תיקיות וחוזה נתונים, בפרק 12**:

- **זרם א (אדם A):** חילוץ טקסט מ-PDF + סיווג שאלות מול הסילבוס.
- **זרם ב (אדם B):** מנוע איחוד כפילויות — עובד מ-fixture, לא תלוי בזרם א בהתחלה.
- **זרם ג (אדם C):** PoC RTL קודם לכול, ואז יצירת מסמך פלט (Word/PDF) + ממשק תצוגה מקדימה/העלאה.

### נקודות סנכרון

- **סנכרון 1 (~4 שעות):** כל אחד מדגים שהמודול שלו עובד מול ה-fixture. זה הרגע לגלות בעיית RTL אצל C — לא בלילה שלפני ההצגה.
- **סנכרון 2 (~10–12 שעות):** A מזרים פלט אמיתי ל-B, B מזרים פלט אמיתי ל-C — בדיקת אינטגרציה חלקית ראשונה.
- **סנכרון 3:** אינטגרציה סופית (ראו שלב 3).

## שלב 3 — אינטגרציה ופריסה
