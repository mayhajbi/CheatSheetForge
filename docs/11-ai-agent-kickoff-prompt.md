# 11. פרומפט פתיחה לסוכן פיתוח AI

מסמך זה מיועד להעתקה ישירה כהודעת הפתיחה לסוכן AI (למשל בתוך Claude Code, לאחר/לצד שלבי BMad) שיתחיל לממש את המוצר. הוא מרכז את כל ההחלטות הסגורות במקום אחד, כך שהסוכן לא צריך לקרוא את כל 10 הפרקים כדי להתחיל.

---

## פרומפט

את/ה עובד/ת כסוכן פיתוח שמממש MVP של מוצר בשם **CheatSheetForge** תחת לחץ זמן קשיח (הדגמה בעוד שעות ספורות). המטרה: קוד עובד מקצה לקצה, לא שלמות. עדיפות לפתרון הפשוט ביותר שעובד על פני הנדסה יתרה.

### מה המוצר עושה

מקבל קובצי PDF של מבחנים/תרגילי בית פתורים (שאלה+תשובה) וקובץ סילבוס של הקורס, מחלץ ומסווג את השאלות, מאחד כפילויות, ומייצא דף נוסחאות מרוכז להדפסה (Word/PDF). כל התהליך בעברית (RTL).

### Tech Stack סופי

- **Backend:** Python + FastAPI.
- **Frontend:** React.
- **LLM:** Anthropic API, Claude (Sonnet כברירת מחדל).
- **חילוץ טקסט מ-PDF:** ספרייה בוגרת קיימת (למשל `pdfplumber` או `PyMuPDF`) — לא מימוש עצמי.
- **יצירת Word:** `python-docx`. **יצירת PDF:** המרה מה-docx (למשל LibreOffice headless), עם WeasyPrint כחלופה אם RTL נשבר בהמרה.
- **בסיס נתונים:** אין. אין התחברות/משתמשים. הכול session-based.
- **שמירה:** מקומית על מחשב המשתמש בלבד (File System Access API בדפדפני Chromium; fallback להורדת קובץ רגילה בדפדפנים אחרים).
- **Deployment:** Railway.

### זרימת המשתמש (MVP)

1. העלאת קובצי PDF (מבחנים/תרגילים פתורים) + קובץ סילבוס.
2. המשתמש מזין כמות דפים מקסימלית רצויה לדף הנוסחאות.
3. המערכת מציגה הודעה: המלצה להעלות מסמכים באיכות גבוהה, וכן מגבלת קבצים להעלאה בודדת (ברירת מחדל להתחלה: עד 15 קבצים / עד 5MB בסך הכול — ניתן לכיול).
4. המערכת מחלצת שאלות+תשובות, מסווגת כל שאלה (סגורה / פתוחה-חישובית / קוד) ומשבצת תחת נושא מהסילבוס.
5. המערכת מאחדת כפילויות (שיפוט LLM חופשי, לא סף כמותי): שאלות סגורות זהות מתאחדות; שאלות פתוחות דומות מתקבצות ל"משפחת נושא" עם דוגמה מייצגת אחת ורשימת וריאציות; שאלות קוד מקבלות הפניה בלבד (לא שכפול טקסט מלא), אלא אם קצרות מספיק לכלול כ"קוד מרוכז".
6. תצוגה מקדימה של הבנק המרוכז, עם אפשרות **הסרת** פריטים (לא עריכת תוכן — זה מחוץ ל-MVP).
7. ייצוא ל-Word ו/או PDF, A4 עם שוליים צרים, בהתאם למגבלת העמודים מסעיף 2 (אם יש יותר תוכן ממה שנכנס, למודל יש שיקול דעת בתעדוף מה נכלל).

### כללים לא-פונקציונליים קשיחים

- **לעולם אין להמציא תוכן.** אם שאלה חסרת פתרון, או קטע קוד חסר במקור — מסמנים זאת במפורש, לא ממלאים מהזיכרון הכללי של המודל.
- מחיקה מלאה של קבצים שהועלו בסיום הסשן, בצד השרת. שום נתון לא נשמר בשרת בין ריצות.
- טקסט עברי (RTL) לצד נוסחאות/קוד/מונחים באנגלית — בשורות נפרדות (LTR בתוך הקשר עברי), לא מעורבבים באותה שורה.
- טבלאות בפלט הן טבלאות docx/PDF מעוצבות אמיתיות — לא טקסט מבוסס "|".
- בבלוקי קוד — סוגריים מפורשים בכל לולאה/תנאי, גם אם הקוד מכווץ.

### סדר עבודה מומלץ (Milestones)

1. **PoC ל-RTL קודם לכל דבר אחר:** ליצור docx/PDF מינימלי עם טקסט עברי מעורב עם נוסחה/קוד באנגלית, ולוודא כיווניות תקינה — לפני השקעה בכל תכונה אחרת. אם המסלול שנבחר (python-docx→LibreOffice) נכשל ב-RTL, לעבור לחלופת WeasyPrint מיד, לא בשעות האחרונות.
2. Pipeline חילוץ+סיווג: קליטת PDF בודד, חילוץ טקסט, קריאה ל-Claude לסיווג שאלה בודדת לפי הסילבוס.
3. מנוע איחוד כפילויות על מספר קבצים.
4. מודול ייצוא docx/PDF מהבנק המרוכז.
5. Frontend: מסך העלאה → תצוגה מקדימה עם הסרת פריטים → ייצוא/שמירה מקומית.
6. אינטגרציה מלאה + פריסה ל-Railway.
7. בדיקת קצה-לקצה עם דאטה אמיתי (מבחני מערכות הפעלה).

### קריטריון קבלה

זרימה מלאה מהעלאת ~5 קבצי PDF ועד קובץ דף נוסחאות מוכן להורדה, תחת 3 דקות, בעברית תקינה מבחינת כיווניות, ללא תוכן מומצא.

### תכונות מפורשות מחוץ לסקופ הנוכחי (לא לממש אלא אם מתבקש)

מבחן לדוגמה, עריכת תוכן פריטים, סיכומים, מפתח מושגים, תמיכה במספר קורסים, מערכת התחברות, בסיס נתונים.

### אם משהו לא ברור

לעצור ולשאול שאלה ממוקדת אחת, ולא לנחש/להמציא החלטת מוצר. פירוט מלא ורקע נוסף לכל סעיף נמצא במסמכי `docs/01` עד `docs/10` באותו repository.

### הערה אם עובדים בכמה זרמים מקבילים

אם שלושה סוכנים/מפתחים עובדים במקביל על חלקים שונים (קליטה+סיווג / איחוד כפילויות / RTL+ייצוא+frontend) — יש לעבוד לפי מבנה התיקיות וחוזה הנתונים המדויק בפרק `docs/12-team-split-and-data-contract.md`, ולא לאלתר מבנה JSON עצמאי.
